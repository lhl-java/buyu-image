## 首件制作流程

1. 用户给出首个具体界面或角色后，整理简短任务单：用途、必含内容、文案、尺寸／比例、透明背景、视角、状态和本次交付范围。已明确的信息不重复确认；缺少关键功能时只补问影响结果的部分。
2. 使用版本化路径保存提示词、设计稿及记录。UI 放 `designs/ui/`，角色放 `designs/characters/`，鱼类与炮台分别放 `designs/fish/`、`designs/cannons/`。
3. 优先使用宿主内置 `image_gen`。按配置记录目标 `gpt-image-2.5-sunburst / max`；工具无 model／quality 选择器时，真实提交值为 null，实际型号和质量按本次返回证据记录，未披露则标为未确认。不转用单独计费 API／CLI。
4. UI 和角色生成／AI 编辑时实际附上相关主参考图；外部截图另标为布局参考，编辑原图另标为编辑对象。文字描述不能替代风格图输入。
5. 每次新生成、重试和 AI 编辑保留提示词及逐图 `<图片名>.generation.json`，包含配置快照、真实提交参数、实际返回证据、输入图用途、尺寸、哈希、时间和验收状态。规则详见 [模型与逐图记录](IMAGE_MODEL_POLICY.md)。
6. 检查风格、轮廓、布局、中文、状态与透明通道，交付首稿供查看。确认设计后再按实际接入需求拆分素材到 `assets/` 对应分类；派生图记录来源、操作、原生及导出尺寸，九宫格记录边距。
