# 捕鱼美术项目长期指令

本目录是用户指定的第二个游戏美术项目，制作捕鱼游戏 UI、角色、鱼类、炮台与配套素材。用户当前明确要求优先。项目独立于相邻 image 美术目录。

## 开始与每次生成前

1. 读取本文件、[图像配置](config/image-generation.json)、[模型与逐图记录策略](docs/IMAGE_MODEL_POLICY.md)。本次用户指定 GPT Image 2.5，优先宿主内置 image_gen；有真实型号和质量参数时显式使用配置值，无选择器则继续宿主管理路径并如实记录。API/CLI 单独计费路线需用户明确选择。
2. 读取 [美术定调与 UI 规范](docs/ART_DIRECTION.md)，实际查看下面两张已确认原图，并在生成／编辑调用中实际附上相关参考图；文件名或文字描述不能代替图片输入。
   - [邮件主参考](designs/mail-ui-v1/01-mail-event.png)
   - [组队主参考](designs/team-ui-v2/team-ui-v2.png)
3. 检查 [素材投递入口](references/incoming/) 和当前任务要求，先确认素材的用途、布局、文案、尺寸、透明背景、视角及状态合同。能独立推进的准备工作继续执行；具体功能未明确时不得把建议清单当作已确认需求。

## 风格与交付

- 以两张主参考及源项目现存 MD 为依据，保持道家 Q 版高清手绘。玉绿／青绿、象牙米白、暖金细边、圆润饱满云纹、细腻明暗；人物大头短身，脸型、服装、法器与身份有区别。鱼、海景和炮台承接同一画法与材质。
- 外部游戏截图仅参考功能、内容与布局，正式游戏名称和文案按用户任务确认。原图中的“五行奇谈”及示例数据不是捕鱼项目设定。
- 新稿使用新版本路径；整屏设计放 designs/ui，角色、鱼类、炮台分别放 designs/characters、designs/fish、designs/cannons。已验收接入资产放 assets 对应分类。切片须沿用对应确认稿，记录透明通道、九宫格、尺寸和来源。
- 每张新图、重试和 AI 修改均保存逐图记录。未披露的实际模型／质量明确标为未确认；复制的旧图保持原历史证据，不回填成新模型。裁切、缩放和拼接注明派生关系与实际原生尺寸。
- 只保留当前设计、游戏成品及接入所需文件。成品落盘且引用完整后可依用户既定规则删除被替代中间图；保留来源文字记录。保留其他窗口当前稿，不恢复用户删除的目录，不整目录删除 docs。
- 本项目当前交付见 [游戏美术状态](docs/GAME_ART_STATUS.json)和[交付说明](docs/GAME_ART_DELIVERY.md)。2026-10-27 用户授权创建并上传到公开仓库 [lhl-java/luhailong-python](https://github.com/lhl-java/luhailong-python)，本项目放在 `buyu-image/`。仅本批目录上传，不操作相邻项目 Git。发布前读取 [本项目发布约定](docs/PUBLICATION_POLICY.md)，固定文件与 SHA256；使用私有 Git 保存单个无父提交，不改共享 HEAD/index/refs。新增计费配置仍需用户明确选择。

## 接续完成标准

参考图须为真实可读图片而非 LFS 指针；每张交付图有独立来源记录与验收状态；设计图、正式切片和客户端接入分别报告。新环境缺失参考时报告缺失，不从旧 Git 或已删除目录补回。
